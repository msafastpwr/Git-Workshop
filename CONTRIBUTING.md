# Contributing

Suggestions and corrections are welcome, especially when they make the workshop easier for students to follow.

If you are new to GitHub contributions, begin with the [collaboration workflow](resources/collaboration-workflow.md). You do not need to be an expert to suggest a typo fix or a clearer explanation.

## Before opening a change

1. Search existing Issues and Pull Requests.
2. Describe the proposed improvement clearly.
3. Keep changes focused; do not add workshop slides to this repository.
4. Check Markdown links and command examples.
5. Remove personal data, credentials, generated files, and editor metadata.

## Writing beginner-friendly improvements

- Explain a new term the first time it appears.
- Show the command before describing its result.
- State whether a command changes files, history, or a remote repository.
- Include a safe recovery step when an action can be confusing.
- Keep workshop topics distinct from additional learning.

## Pull Request checklist

- [ ] The change is based on the workshop topics or clearly labeled additional learning.
- [ ] Commands use valid Git syntax and explain any placeholders.
- [ ] Markdown headings and links render correctly.
- [ ] The change does not include secrets or duplicate presentations.
- [ ] The description explains what changed and how it was checked.

Use a feature branch and submit a Pull Request for review. Keep commits small and descriptive.
